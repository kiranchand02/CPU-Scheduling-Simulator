CPU Scheduling Documentation

Explore the concepts, algorithms, and execution strategies used in CPU process scheduling.

What is CPU Scheduling?

CPU scheduling is the process of selecting which process should execute next. The operating system chooses a process from the ready queue based on a scheduling algorithm to improve CPU utilization, system performance, and resource allocation.

Why CPU Scheduling Matters

CPU scheduling plays a vital role in multitasking operating systems by deciding which process should execute next. It helps maximize CPU utilization, improve system performance, reduce waiting time, and ensure fair allocation of processor resources among multiple processes.

Objectives of CPU Scheduling

  • Maximize CPU utilization.
  • Ensure fair process execution.
  • Increase system throughput.
  • Reduce turnaround time.
  • Minimize waiting time.
  • Improve response time.

Key Terminology

  • Burst Time: CPU time required for a process to complete execution.
  • Arrival Time: Time at which a process enters the ready queue.
  • Completion Time: Time when a process finishes execution.
  • Turnaround Time: Total time from arrival to completion.
    Turnaround Time = Completion Time − Arrival Time
  • Waiting Time: Time spent waiting in the ready queue.
    Waiting Time = Turnaround Time − Burst Time
  • Response Time: Time from arrival until the process first gets CPU access.
  • Ready Queue: Queue of processes waiting for CPU allocation.
  • Process: A program currently being executed by the operating system.
  • CPU–I/O Burst Cycle: Alternating sequence of CPU execution and I/O operations.
  • Multiprogramming: Running multiple processes in memory to improve CPU utilization.

Types of CPU Scheduling

CPU scheduling algorithms are classified into two types based on whether a running process can be interrupted before completion.

Preemptive Scheduling

A running process can be interrupted and replaced by another process with higher priority or shorter remaining execution time.

Non-Preemptive Scheduling

Once a process starts executing, it continues until completion or until it voluntarily releases the CPU.

Comparison

  • Preemptive: Allows process interruption, provides better responsiveness, and is ideal for multitasking environments.
  • Non-Preemptive: Does not interrupt a running process, offers simpler implementation, and reduces context-switching overhead.

Scheduling Algorithms Implemented

  • First Come First Serve (FCFS)
  • Shortest Job First (SJF)
  • Shortest Remaining Time First (SRTF)
  • Round Robin (RR)
  • Priority Scheduling

1. First Come First Served (FCFS)

First Come First Served (FCFS) is the simplest CPU scheduling algorithm. Processes are executed in the order they arrive in the ready queue, following the First-In, First-Out (FIFO) principle.

Advantages

  • Simple and easy to implement.
  • Processes are executed fairly in arrival order.

Limitations

  • Long processes can delay shorter ones (Convoy Effect).
  • May result in high average waiting and turnaround times.

2. Shortest Job First (SJF)

Shortest Job First (SJF) schedules the process with the smallest CPU burst time first. It is designed to minimize average waiting and turnaround times, making it one of the most efficient scheduling algorithms.

Advantages

  • Reduces average waiting and turnaround times.
  • Efficient for workloads with shorter processes.

Limitations

  • Requires an estimate of CPU burst time.
  • Long processes may experience starvation.

3. Shortest Remaining Time First (SRTF)

Shortest Remaining Time First (SRTF) is the preemptive version of SJF. The CPU is always allocated to the process with the shortest remaining execution time, allowing newly arrived shorter processes to preempt the current one.

Advantages

  • Minimizes average waiting and turnaround times.
  • Provides better responsiveness for shorter processes.

Limitations

  • Frequent context switching increases system overhead.
  • Long processes may experience starvation.

4. Round Robin (RR)

Round Robin (RR) is a preemptive scheduling algorithm that allocates each process a fixed time quantum in a cyclic order. It provides fair CPU access and is widely used in time-sharing operating systems.

Advantages

  • Ensures fair CPU allocation for all processes.
  • Prevents starvation and improves system responsiveness.

Limitations

  • Choosing an inappropriate time quantum can reduce performance.
  • Frequent context switching may increase system overhead.

5. Priority Scheduling

Priority Scheduling executes processes based on their assigned priority. Processes with higher priority are scheduled before lower-priority ones, making it suitable for systems where certain tasks require immediate attention.

Advantages

  • Ensures high-priority tasks are executed promptly.
  • Provides flexible scheduling based on process importance.

Limitations

  • Low-priority processes may experience starvation.
  • Determining appropriate priority levels can be challenging.
